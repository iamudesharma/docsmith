# Validation evidence — 12 October 2026

The final local build, formatting and Clippy (`--all-targets -D warnings`) pass on Rust 1.88/macOS ARM64. **39 tests** pass. **30 live API checks** pass, including multipart upload, canonical cells, compact tables, JSON/Markdown/plain text, unit/asset retrieval, auth/tenant cache isolation, both upload/body 413 limits, queued/running/duplicate cancellation, delete-while-running, enforced process timeout, crash restart, two-worker concurrency, disk quota rejection, cache-hit quota bypass, retention sweep and deletion. See VALIDATION.json and e2e-results.json.

The unit suite covers source graphs and compressed/embedded source, exact synthetic table cells/formulas/merges, legacy BIFF8 XLS typed values and formula/cached results, macro-enabled XLSM never exposing or executing VBA source, DOT warning behavior, logical source order, OCR rotation coordinate mapping, hidden OCR suppression, password/corrupt inputs, XML/entity/archive defenses, PDF geometric table proposals, chart caches, valid OpenAPI references and completed-page checkpoint reuse. Macro code and external resources are never executed/fetched by the direct adapters.

The Xberg process adapter is now verified end-to-end (CLI and HTTP worker): an ANSI-colored `xberg version` output had made the exact-match version gate fail, so every Xberg extraction reported a message-less `unsupported`; `NO_COLOR=1` plus a tolerant version parse fixed it, adapter errors are now surfaced in warnings, and `extract --parser xberg` exists. Evidence: docs/xberg-adapter-check.json. The canonical Xberg mapping remains partial.

A generated 10,000-row/30,003-cell CSV completes in about 510 ms of extractor time (1.10 s CLI wall time) in a debug build, retaining leading zeros. JSON/Markdown/plain text/unit/assets are streamed; lightweight status and asset manifests avoid reparsing large results when polling. See large-input-check.json.

Large synthetic inputs were measured after the batching and parallelism work (see perf-large-inputs.json): a 3000-page text PDF completes in about 21 s in a release build with four batch workers (~30 s with one, ~62 s debug; 3000 page units, no errors), and an unchanged 500-page job reuses every page in ~0.5 s. Parallel and sequential worker counts produce byte-identical results in a dedicated test. A 700k-row/30 MB CSV completes in ~3.3 s release (~0.9 GB peak memory, ~356 MB result); `compact_tables` cuts a 400k-row result from 203 MB to 68.5 MB. Before this work the PDF exceeded the default unit limit and timeout (extrapolated ~9 minutes at the old per-page rate) and the CSV failed at the 1M-cell cap. These are synthetic inputs; scanned/mixed real corpora remain the practical constraints.

Tesseract's clean/noisy/rotated English and Hindi synthetic fixtures have zero normalized character error in the 12 October rerun. Apple Vision builds, lists languages including `hi-IN`, and reports supported languages at runtime, but every rerun image failed with `e5rt` execution errors (~61 s per image) even though the helper selects CPU compute devices; its local reliability gate has **not** passed. Do not treat runtime language availability as recognition reliability.

SmolVLM2 Q4 plus matching Q8 projector completed native local inference in repeat runs (server sampled peak RSS 0.49–0.89 GB; invoice description correct; constrained ER JSON syntactically valid but semantically wrong — Users/Orders mislabeled as PK/FK, expected endpoints absent, entity recall 0). Canonical graph output remains inferred with warnings; the model did **not** pass diagram semantic acceptance. See benchmark-results.json and vlm-memory-summary.txt. The temporary server was stopped after testing.

The brief's M1 Pro 16 GB, real customer scans/handwriting, complex layout/topology, full legacy formats, Visio/SmartArt graph semantics, Paddle/ONNX complete OCR pipeline, stronger-model comparison, container runtime, long soak and backup-restoration gates remain unrun or deferred. Linux execution is provided by `.github/workflows/benchmark.yml` (manual `workflow_dispatch` or weekly); results appear as CI artifacts once the repository is pushed, and this local checkout cannot run them. Docker/CI/deployment artifacts are provided; the local Docker socket was unavailable. Per-tenant disk quotas and retention sweeps are opt-in via `limits.disk_bytes`/`limits.retention_seconds`. The service is a tested foundation, not a claim of exhaustive document fidelity or completed production certification.
